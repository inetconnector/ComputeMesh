Validated and remaining boundaries

✅ Software foundations

Authenticated gateway/provider-control paths, runnable public provider agent, durable orchestration/recovery mechanics, signed private placement decisions, execution evidence/attestations and measured-outcome feedback are implemented foundations.

🔬 Physical evidence

A narrow trusted-lab two-machine llama.cpp shared-runtime proof is recorded for its exact hardware/model/runtime/topology. It is not a universal performance or production-readiness claim.

🔒 Runtime security boundary

Upstream llama.cpp RPC remains experimental and is not a public ComputeMesh security boundary. Current development bring-up contains it behind trusted/private networking or SSH tunnels.

🧪 Remaining readiness gates

Representative LAN/WAN measurement matrices, provider-enforced resource leases, production data-plane and key/session hardening, adversarial/system testing, calibrated private performance prediction and production operations/HA remain open.

About status metrics

This page deliberately does not display placeholder global VRAM, GPU count, uptime or gateway-latency numbers as though they were live. Such metrics should appear only when sourced from an authenticated current registry/telemetry path. Until then, unavailable means unavailable.
