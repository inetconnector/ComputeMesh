Current architecture

Implemented foundations with explicit readiness limits

ComputeMesh separates public execution/protocol/provider code from private production placement/data/policy.

🧩

Measured layer splitting

Contiguous two-node layer splits are researched and validated per exact model/runtime/hardware/network evidence. No universal speedup is assumed.

⚡

Heterogeneous provider foundations

Hardware inventory and CUDA/ROCm/Vulkan-related tooling exist, but production support is validated per actual target rather than claimed for arbitrary GPU mixes.

🧠

Private production placement

The public runtime receives a signed execution plan; production ranking, empirical performance, reputation/fraud and economics remain private.

🌐

OpenAI-compatible gateway

Supported OpenAI-style endpoints are implemented. This is not a claim of compatibility with every OpenAI API or SDK behavior.

📦

Provider/NodeOS tooling

Windows/Linux/provider and appliance tooling exists for supported engineering targets. Exact driver/GPU combinations still require validation.

🔒

Evidence & accounting foundations

Execution evidence, provider attestations, durable feedback and double-entry ledger foundations exist. Settlement/payout policy is deployment- and private-policy-dependent.

Integration

OpenAI-compatible supported surface

Point a compatible client at the deployment's `/v1` base URL, use a registered API key and choose an actually exposed model. Check `/v1/models` and current API documentation rather than assuming every OpenAI endpoint exists.

inference_example.py
from openai import OpenAI

client = OpenAI(
    base_url="https://computemesh.inetconnector.com/v1",
    api_key="cm_live_your_registered_key"
)

models = client.models.list()
# Select a model actually exposed by the active deployment.
