# ComputeMesh Image Generation Safety & Compliance

Status: **mandatory production gate** for every image-generation or image-editing backend.

This document describes the technical policy implemented by `services/gateway/image_safety.py` and `services/gateway/image_generation.py`. It is not a substitute for jurisdiction-specific legal advice.

## Core invariant

No image backend may be exposed directly to users. The only supported architecture is:

`request -> prompt moderation -> policy decision -> image backend -> output moderation -> provenance -> response`

If prompt moderation or output moderation is unavailable, generation fails closed. Model output is never returned before the output classifier has approved it.

## Public ComputeMesh policy

### Always blocked

The public service blocks at minimum:

- sexual content involving minors, minor-coded subjects, or uncertain age;
- explicit sexual/pornographic generation;
- non-consensual intimate imagery;
- sexualized real-person/deepfake generation;
- fraudulent identity documents and materially deceptive identity assets;
- terrorist/extremist propaganda or recruitment;
- exterminatory/dehumanizing targeted hate content;
- content materially facilitating dangerous wrongdoing.

Age ambiguity is treated conservatively: if sexual content is present and the classifier cannot establish an adult age range, the request/output is blocked.

### Context review / restricted

The following categories require enhanced contextual review and are not emitted from the anonymous/public image endpoint without a separate reviewed workflow:

- real-person imagery;
- graphic violence;
- self-harm imagery;
- graphic medical imagery.

Context matters. Documentary, journalistic, historical, scientific, educational and artistic material must not be reduced to a simple symbol blacklist. Where the legal/product context permits it, such content belongs in a review path rather than an automatic allow path.

### Normally allowed

Ordinary non-sensitive creative content such as landscapes, architecture, product concepts, diagrams, fictional characters, animals and non-graphic art can be generated when both moderation stages return `ALLOW`.

## Real persons and deepfakes

Real-person generation is a sensitive category. The anonymous/public path does not auto-approve it. Sexualized real-person/deepfake content is always blocked. Product deployments that later support benign real-person transformations must add consent/authority checks, impersonation safeguards and jurisdiction-specific notices before enabling the feature.

## Input images

Image editing must run the same multimodal classifier on every uploaded image before processing. Implementations should:

- strip EXIF/GPS metadata unless there is a documented need to retain it;
- avoid face recognition/identity matching by default;
- minimize retention and exclude raw images/prompts from ordinary application logs;
- reject unsupported or malformed image formats before model execution;
- scan uploaded content for the same minor/sexual/deepfake/violence categories used on generated output.

## Output provenance and AI transparency

Every successful result includes machine-readable provenance fields:

- `generated_by_ai: true`;
- generator and model identifier;
- creation timestamp;
- prompt SHA-256 (not the raw prompt);
- asset SHA-256;
- provenance format version.

Deployments should additionally embed a signed C2PA/Content Credentials manifest when a production signing implementation is configured. The public UI should clearly state that the image is AI-generated/manipulated where required.

## DSA-style notice/action readiness

If ComputeMesh later stores, publishes or shares generated images, the hosting layer must provide:

- an accessible report/notice mechanism;
- stable moderation reason codes;
- audit records that do not unnecessarily retain raw sensitive content;
- a user-facing explanation of moderation decisions;
- an appeal/review workflow where applicable;
- rapid disable/removal paths for illegal content.

The image safety engine already returns stable `IMG_SAFETY_*` reason codes for this purpose.

## Required moderation implementation

`ImageSafetyOrchestrator` requires two independent classifier call sites:

1. prompt/input classifier: multilingual text and, for edits, multimodal input classification;
2. output classifier: multimodal classification of the actual generated bytes.

A lexical prefilter exists only as a fast first layer. It must never be treated as the complete production moderation system.

Recommended classifier capabilities:

- DE/EN plus multilingual semantic classification;
- obfuscation/leetspeak/euphemism robustness;
- minor/age-range estimation with uncertainty;
- explicit sexual content;
- non-consensual intimate/deepfake cues;
- real-person likelihood;
- hate/extremism context;
- graphic violence and self-harm;
- OCR/text-in-image analysis where relevant.

## Logging and privacy

Do not log raw prompts or raw image bytes in normal request logs. Store only what is operationally necessary, such as request id, timestamps, model id, decision, reason codes, hashed prompt/asset identifiers and classifier version. Security/legal retention must be separately documented and access-controlled.

## Product wording

Vision-capable chat models must be labelled as image **analysis/understanding** unless they actually implement image generation. The portal must not imply that a vision-language model can render an image when only `/v1/chat/completions` is available.

## Release gate

Image generation is not production-ready unless all of the following pass:

1. prompt moderation is configured and fail-closed;
2. upload moderation is configured for image editing;
3. output moderation is configured and fail-closed;
4. under-18 + sexual test cases are blocked, including ambiguous ages;
5. non-consensual sexual/deepfake test cases are blocked;
6. explicit sexual public generation is blocked;
7. real-person sensitive cases route to review;
8. output bytes cannot escape before moderation;
9. provenance is attached to every successful result;
10. red-team tests cover multilingual and obfuscated prompts;
11. privacy/logging review is complete;
12. deployment-specific legal review is complete.
